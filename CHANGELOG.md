# Changelog

All notable changes to PHP Station are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- **AI agents over MCP** (`tools/mcp.js`, `lib/mcp.js`). A stdio Model Context Protocol server (protocol 2024-11-05 to 2025-06-18) for Claude Code, Cursor, VS Code Copilot, Codex and Claude Desktop. It talks to the running panel with the token from `panel.json` (and starts the panel without a window when it is closed). 14 tools: `list_projects`, `project_errors`, `project_log`, `list_mail`, `read_mail` (links and OTP-like codes, HTML-only mail read as text), `list_dumps`, `db_history`, `undo_db_action`, `list_restore_points`, `create_restore_point`, `restore_database`, `start_project`, `stop_project`, `doctor`. Tools that change something carry `destructiveHint` / `readOnlyHint` annotations. Without a `project` argument the project of the agent's folder is used (deepest match), else the only running one. Answers are trimmed so they never flood the agent's context. **Settings → AI agents** shows the config for each tool (`GET /api/mcp/config`).
- **Upgrade Lab** (`lib/upgradelab.js`, project card ⋯ menu). Tests a project on another installed PHP version without changing it: `composer.lock` packages whose own `php` constraint excludes the target, the `composer.json` constraint, `ext-*` extensions the target does not load; every app file linted with the target PHP and every deprecation it reports (Blade views, `vendor`, `storage`, `build` left out); and every GET page (from `route:list --json`, or links crawled from `/` for plain PHP) opened on the running project and on a temporary fast server of the same folder on the target PHP. Per page it compares the status, redirects, PHP errors printed into the page and the log lines the request added (`storage/logs`, both PHP server logs). The test server reports what the current one reports plus `E_DEPRECATED`, with opcache off so compile-time deprecations are reported, and its PHP errors in its own file. Routes that sound like a change (`logout`, `delete`, `reset`, `cache/clear` ...) and debug routes are skipped. Options: a session cookie for pages behind a login (never stored or logged), the number of pages, and a Time Machine restore point first. Verdict: ready / runs with warnings / not ready, with file:line links.
- **Security scan** (`lib/secscan.js`, project card ⋯ menu). `composer audit --format=json --locked` with the project's PHP and Composer (known CVEs and abandoned packages; packagist.org receives the package names and versions), a code scan with [vibe-security](https://github.com/sami-hussain-dev/vibe-security) (an npm-installed copy, or fetched from GitHub with npx the first time, after the user ticks it), and serving checks: `APP_DEBUG=true` with `APP_ENV=production`, empty `APP_KEY`, `.env`, `.git`, `phpinfo()` files and `.sql` / `.zip` backups in the public folder.
- **QR code for the live link** (`public/qr.js`): a small QR encoder (byte mode, level M, versions 1–10) draws the code in the panel, so the link never goes to a QR service. Shown in the live link dialog and from a phone button on the share strip.
- Job modals can be wider (`showJob(..., {size})`) for reports.
- **Instant restore points for any database size.** On MariaDB servers that write the DB History binlog, a restore point before `php artisan migrate` / `db:*` is now a marker: the binlog position, saved in about 0.2 s whether the database has 1 MB or 1.2 GB. Going back imports the newest base copy and replays the binlog up to the marker (point-in-time restore), so `TRUNCATE`, `ALTER` and `DROP` are undone too. Base copies are full dumps that record their binlog position (`--master-data=2` on a consistent snapshot, no table lock). They are written in the background (job `tm-base`): 20 s after the panel starts, every 10 minutes when one is missing or older than a day, after a project starts and after an undo or import. A marker can rely on a base that is still being written. A base is used only within the same server run and never across a write that is not in the binlog (Time Machine undo, Import database, recorded in `unlogged.json`). Without a base the old blocking dump runs once, and it becomes the base for the next command. An undo to a marker saves the current state first, as a marker when it can. If the replay fails, it puts that state back.
- **Import database** (`lib/dbimport.js`, project card button). Imports a `.sql`, `.sql.gz` or `.zip` dump into the project's database (or another name). The dump is checked first: MySQL 8 collations (`utf8mb4_0900_ai_ci`), `utf8mb3`, `DEFINER`s, GTID / `SQL_LOG_BIN` lines, MySQL 8 `/*!80xxx */` parts, `0000-00-00` dates under strict mode, lines longer than `max_allowed_packet`, files that are not UTF-8, UTF-16 files and `USE` / `CREATE DATABASE` lines that would send the tables elsewhere. Each finding comes with its fix switched on. A Time Machine restore point (`pre-import`) is saved first when the database has tables. The dump streams through the fixes in one session with foreign key checks, unique checks and autocommit off. When the server stops the import, the panel shows its error, the dump line it came from and "Fix and import again", which reruns the import with the matching fix.
- **`.htaccess` without Apache** (`lib/htaccess.js`, `tools/htrouter.php`). For projects without their own router, the fast server applies the docroot's `.htaccess` files the way Apache does in per-directory context: `RewriteEngine` / `RewriteBase` / `RewriteCond` (`-f`, `-d`, `-s`, regex, `=`, `[NC]`, `[OR]`, `%{REQUEST_FILENAME}`, `%{HTTP:X}` ...) / `RewriteRule` (`$n` / `%n`, `[L]`, `[END]`, `[R=301]`, `[F]`, `[G]`, `[QSA]`, `[QSD]`, `[S=n]`), internal rewrites that run again on the new path, `Redirect` / `RedirectMatch`, `Require all denied` / `Deny from all` / `<Files>` / `<FilesMatch>`, `DirectoryIndex`, `DirectorySlash`, `ErrorDocument` and `Header set / append / unset`. `.ht*` files are never served. A rewrite to a script runs through `tools/htrouter.php` with the original `REQUEST_URI` and the new `SCRIPT_NAME`, `PHP_SELF`, `QUERY_STRING` and `$_GET`. The internal header that carries the target is signed with a per-run token and removed from client requests. Lines that are not applied are written to the project log and listed on the card (`HTACCESS_PARTIAL`). Setting `htaccess` (default on).
- **Doctor** (`lib/doctor.js`, top bar). Checks for a newer PHP Station (GitHub release, else the default branch), broken PHP folders, project and DB server problems, running MariaDB / MySQL servers still on the XAMPP defaults, Windows Defender scanning the datadirs and free disk space. Each finding has its fix: **Apply faster settings** sets `innodb_buffer_pool_size` (1/8 of the RAM, 256 MB to 1 GB) and `max_allowed_packet` (256 MB) on the running server and in its `my.ini`, after copying the old file to `data\config-backups`. **Defender exclusion** adds only the DB datadirs, after a confirmation and a Windows administrator prompt. **Copy report** gives an English Markdown report for GitHub issues with the user name, PC name and every path masked.
- **Files menu** on the project card (`lib/configfiles.js`): `.env`, the PHP folder's own `php.ini`, the DB server's `my.ini`, `laravel.log`, the DB error log, `.htaccess`, `composer.json` and the Windows hosts file open in the editor from Settings (VS Code, Cursor, PhpStorm, Sublime Text), else in Notepad. The browser only sends a key; the path is looked up on the server.

### Changed
- **Restore points before `php artisan migrate` / `db:*` are much faster.** The panel answers in one query, without a dump, when nothing is pending (`migrate` with no new migration files, including package migrations) or when the server's write counters show nothing was written since the newest restore point. Otherwise one `mariadb-dump` runs without per-table trigger lookups when the database has no triggers, and big databases (64 MB and up) are dumped in up to 4 parallel parts. The shim passes the whole artisan command, the terminal polls every 100 ms and prints only one line. Measured on a 192-table database: "Nothing to migrate" 6 s → 0.1 s, unchanged database 6 s → 0.2 s.

### Fixed
- A datadir the signed-in user may not write to (EPERM / EACCES on `ibdata1`) is no longer reported as "another program is using the datadir". The new message (`DATADIR_NO_ACCESS`) names the permission problem and its two fixes: start the server from Laragon / XAMPP, or grant the user access with `icacls` in an Administrator terminal.

## [1.3.0] - 2026-11-13

### Added (Inbox)
- **Inbox page: Mail, Dumps, Errors.** A new sidebar page with unread counts, toasts when something new arrives, a project filter and file:line links that open in VS Code, Cursor, PhpStorm or Sublime (setting `editor`).
- **Mail Catcher** (`lib/mailcatch.js`). A local SMTP server on `127.0.0.1:1025` (settings `mailCatcher`, `mailPort`) keeps every email of projects started by PHP Station: HTML in a sandboxed frame with desktop and mobile widths, text, headers, attachments, `.eml` download, Bcc from the SMTP envelope, and the sending project. Nothing is relayed. The newest 500 are kept in `<data>\mail`. A connection that speaks HTTP is closed.
- **Dumps** (`lib/dumps.js`, `tools/dumpdecode.php`). `dump()` / `dd()` of web requests go to a dump server on `127.0.0.1:9912` (settings `catchDumps`, `dumpPort`) through Symfony's `VAR_DUMPER_FORMAT=server`, and are shown as collapsible trees with file:line and URL. They are decoded with the project's own PHP and only the `symfony/var-dumper` classes; `unserialize` may create only VarDumper's Data and Stub classes.
- **Errors** (`lib/devlogs.js`). `storage/logs/*.log` and the PHP server log of each project are parsed: level, exception, file:line and stack frames, with your own code first and vendor frames folded. Repeats are grouped, and new errors are counted on the project card. The log files are read only; "Mark all seen" stores a byte position in the panel state.
- **Dev tools prepend** (`lib/devtools.js`). One `auto_prepend_file` for project servers and the `php.bat` shim, so mail from `queue:work` is caught too. It acts only while the panel's heartbeat file (`<data>\devtools\live.json`) is fresh. It sets `MAIL_*` for the request (process env wins over `.env`) and SMTP / `smtp_port` for `mail()`. The `.env` file is never changed. The share prepend chains it.
- **Open from GitHub** (`lib/gitclone.js`). Paste a GitHub / GitLab / Bitbucket / ssh link or `owner/repo`. PHP Station clones it with the installed Git, then runs the team-file plan even without a `phpstation.json` (database from `.env.example`; SQLite gets `database/database.sqlite`) and starts the project. Option-like, local and `ext::` links are refused, and an existing non-empty folder is never used.

### Changed
- README rewritten: a short pitch, a "why" table, quick start first, one section per feature with screenshots, an updated comparison, and new FAQ entries.

### Fixed
- Live link: an error line of cloudflared (`https://api.trycloudflare.com/tunnel`) was taken as the link. The link now counts only after the tunnel has connected, and there are up to 3 attempts when Cloudflare is slow to answer.

### Added
- **Shift from XAMPP / Laragon / WAMP.** Finds projects in `htdocs` / `www` and in Apache / nginx virtual hosts (Laragon `auto.*.test.conf`, XAMPP `httpd-vhosts.conf`). Each project keeps the PHP and DB server it used before. Read-only: nothing in the old stack is changed.
- **DB Time Machine.** Restore points of a project's database are made by hand, and automatically before `php artisan migrate*` / `db:*` in PHP Station terminals (php.bat shim → `tools\restore-point.js`; the command is never blocked). Undo first saves the current state, test-imports the point into a scratch database, and only then replaces the real database (it puts the old state back if the import fails). New settings: `pointBeforeArtisan`, `pointKeep`.
- **Live share link.** A Cloudflare quick tunnel (`cloudflared`, installed from the official GitHub release with a SHA-256 check) for a running project. An `auto_prepend_file` makes Laravel see HTTPS for tunnel requests only. Shares end with the project or the panel. A warning is shown when a Vite dev server is running.
- **DB Time Machine, Every action.** MariaDB servers that PHP Station starts keep a row-based binary log (in the backup folder, no my.ini change, settings `dbHistory` / `historyDays`). Time Machine lists every INSERT / UPDATE / DELETE of the project database with its SQL and old / new values, and undoes ONE action with `mariadb-binlog --flashback` (conflicting later changes are shown first). A baseline restore point is taken when a project is added.
- **Fast server.** On Windows `php -S` answers one request at a time, so every CSS / JS / image of a page waited behind the page itself (2.4 s in a test, now 2–7 ms). Projects now run behind a small Node server (`tools\fastserve.js`) that serves static files directly (never `.php` or dot-files) and spreads PHP requests over N `php -S` workers (setting `phpWorkers`, default 4; 1 = plain `php -S`).
- **`phpstation.json`.** Plan + one job: installs missing PHP / MariaDB / Composer, enables extensions (only in PHP Station's own PHP builds, `php.ini` backed up first), registers the project, starts its DB server, runs `.env` / `composer install` / `key:generate` / database / `migrate` / `db:seed` / `storage:link`. Export from any project card. JSON schema in `docs/phpstation.schema.json`.

## [1.2.0] - 2026-11-12

### Changed
- **New name: PHP Station** (formerly *DevPanel*). The launchers are now `PHP-Station.bat` and `PHP-Station-Stop.bat`. Existing data, settings, backups and environment variables (`DEVPANEL_*`) keep working unchanged.
- The shutdown guard is now `PHPStationGuard.exe`; a running guard from an older version is replaced automatically.
- The DB card footer no longer clips on narrow layouts ("Change port" is in the ⋯ menu).

### Added
- **Desktop and Start Menu shortcuts** are created automatically on the first start of an install, once per install folder. Old `DevPanel.lnk` shortcuts that point into the same folder are removed.
- **Setup wizard**: shows what is installed and what each project needs, selects versions automatically, and installs PHP, MariaDB, Composer and phpMyAdmin in one batch.
- **phpMyAdmin**: PHP Station runs its own copy (official download or copied from XAMPP/Laragon), lists every DB server on its own port, and opens a project's database directly.
- **Crash safety**: shutdown guard (clean DB stop on Windows shutdown/sign-out), automatic data-folder snapshots, daily `.sql` dumps, restore without overwriting, one-click repair from the error log, and InnoDB rescue on a copy.
- **Automatic DB start**: when a project runs, its DB server starts by itself. If a Laragon/XAMPP server already serves the same data folder (even as admin), that server is used.
- **`DB_PORT` override**: if `.env` names another port, the correct one is passed through the environment, and `.env` is not touched.
- **"Show paths"** per project (PHP, php.ini, Composer, DB server, datadir, project) with copy buttons.
- Links open in the system's default browser.
- Brand assets: logo, Windows icon, social preview; README screenshots; GitHub templates; `llms.txt`.

### Fixed
- phpMyAdmin no longer warns that `session.gc_maxlifetime` is lower than the cookie validity.
- A panel started with another data folder (a test run or a temporary panel) can no longer take over or stop the shutdown guard of the real install.

## [1.1.0]

- Projects with their own PHP, Composer and DB server; external `php -S` servers; DB servers and new instances; DB Move; missing-database flow; `.env` setup checklist; installer for PHP, MariaDB and Composer from official sources (SHA-256); English, Roman Urdu and Urdu UI.
